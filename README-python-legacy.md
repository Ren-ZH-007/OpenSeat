# OpenSeat 0.1 — Windows 多座位配置开发版

**此包是可运行源码，不是已编译安装程序，也不是完整 ASTER 替代品。它还不能让多人同时操作独立 Windows 桌面。**

依据所提供的 ASTER 功能说明进行独立实现，未使用 ASTER 的代码、驱动、图标或商标素材。

## 启动

1. 在 Windows 10/11 上安装 Python 3.10 或以上版本，包含 tkinter 与 Python Launcher。此为目标运行环境，尚未经 Windows 实机验证。
2. 解压本压缩包，双击 `start-python-config.cmd`。也可在该目录运行 `py -3 app.py`。
3. 点“扫描真实设备”；选中右侧设备和左侧工位，点“分配到左侧选中工位”。
4. 点“检查配置”查看缺少的键鼠/显示器与离线设备；点“保存配置”持久化。
5. 无 Windows 设备时，可点“演示设备”验证配置交互。演示设备均带 DEMO 前缀。

运行只依赖 Python 标准库。设备扫描调用 Windows PowerShell 的 Get-PnpDevice，只读取设备清单。扫描最多等待 40 秒，可见设备范围和返回结果取决于 Windows 环境。

## 数据与行为

默认配置：`%LOCALAPPDATA%\OpenSeat\config.json`。界面分配修改保存在内存，点击保存才落盘。导入经过格式检查后成为待保存配置；文件损坏时提示错误并保留原文件，只有用户主动保存才覆盖。

每个设备实例 ID 只有一个工位归属，重新分配会替换旧归属。未分配只表示配置中没有指定工位，并不提供系统层公共共享模式。USB 复合设备可能产生多个 PnP 节点；拔插到不同接口可能改变实例 ID，需要重新核对。音频端点数量不等于物理音响数量。

演示数据可以保存，因此切回真实扫描后 DEMO 分配会显示为离线；可选中后取消分配。配置只记录工位名与设备实例 ID，不存储密码。导出的配置包含硬件标识，分享前可自行检查。

没有权限管理界面。程序不修改 HVCI、防火墙、Defender、电源策略或 Windows 会话限制。后续驱动安装所需的 Windows 管理员权限不属于应用角色权限，不能通过取消应用权限体系消除。

## 打包 EXE

在 Windows 上运行 `build-python-config.cmd`。它建立本地虚拟环境，通过 pip 下载 PyInstaller 并构建 `dist\OpenSeat\OpenSeat.exe`。需要网络访问 Python 包源。分发时复制整个 `dist\OpenSeat` 文件夹。

本交付环境未执行 Windows 打包；不包含签名 EXE、不承诺打包成功。可直接先使用源码启动脚本。

## 验证

执行：`py -3 -m unittest discover -s tests -v`。

本次已执行 6 个跨平台配置测试：读写往返、无效引用不会覆盖已有配置、单设备单归属、离线/缺失提示、演示完整配置仍标记引擎未实现、无效格式和工位边界拒绝。

尚需在 Windows 上验证：首次启动、扫描真实设备、设备断开后刷新、中文路径保存、导入损坏 JSON、取消退出、EXE 打包。当前 Linux 环境未进行 GUI 和 Windows 硬件实测。

## 完整多座位引擎的后续开发边界

这不是加入一个“启动”按钮即可完成的功能。下一阶段首先需要 Windows 测试机、目标 Windows 版本、显卡/显示接口与两套 USB 键鼠信息，用于验证可行的会话和设备绑定方案。

1. 单独做双工位技术验证：两个独立桌面同时显示，键鼠不串扰；方案必须先通过该门槛。
2. 设计带版本和能力协商的本地服务接口；只有引擎实际确认能力后才能开放启动工位操作。
3. 实现与验证输入、图形和音频路由，设备热插拔回退，以及主工位恢复。Raw Input 只提供设备输入信息，本身不能视为整个 Windows 桌面的独占输入隔离机制。
4. 完成需要的驱动开发、签名、恢复/卸载路径，再接入配置界面。驱动技术方案尚未确定，本包不伪造可用驱动骨架。
5. 先验收 2 工位，再逐步增加负载和工位数。GPU 共享、DisplayLink、多屏、USB Hub 和应用兼容性分别实测。

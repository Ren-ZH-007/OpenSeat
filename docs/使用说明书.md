# OpenSeat 0.2 中文使用说明书

适用版本：OpenSeat 0.2.x ～ 0.3.0　·　平台：Windows 10 及以上 x64

---

## 1. OpenSeat 是什么

OpenSeat 0.2 是一个**三工位技术验证工具**。它回答一个问题：在一台 Windows 电脑上接三台显示器、三个鼠标（和可选的三个键盘）时，程序能不能**分清每一个物理设备**，并把它的输入只送到对应工位的屏幕上。

它能做的：

- 识别 Windows 当前启用的显示器，并在每块屏幕上显示编号。
- 通过 Windows Raw Input 识别每一个物理鼠标和键盘。
- 把鼠标、键盘和显示器绑定到三个工位，并保存配置。
- 在三块屏幕上各打开一个测试窗口，用蓝色测试指针和计数器显示“哪个设备在动”。

它**本身不能**做的（请务必了解）：

- 单靠 OpenSeat 不能让三个人各自独立使用 Windows 桌面或任意软件。**0.3.0 起，配合 VMware 虚拟机可以做到**：一个工位用主机 Windows，另外两个工位各运行一台 Windows 虚拟机，详见第 14 节。
- 系统鼠标光标、桌面、音频和其他软件仍然由三套设备**共享**。
- 不做 GPU、音频、USB 或磁盘隔离；不是安装程序，也不安装驱动。

> 简单说：OpenSeat 0.2 只证明“设备能被区分、屏幕拓扑正确”，是多工位系统的第一步，不是完整的多工位系统。

## 2. 运行环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 或更高版本，64 位 |
| 运行库 | .NET Framework 4.x（Windows 10/11 一般已自带） |
| 显示器 | 3 台，Windows 显示设置中必须为“扩展这些显示器”，不能是“复制” |
| 鼠标 | 3 个，最好各用独立 USB 接收器或有线连接 |
| 键盘 | 可选，0～3 个 |
| 显卡 | 目标为 RTX 3050 及以上，但程序不检查显卡，也不保证兼容 |
| 权限 | 普通用户即可，不需要管理员 |

## 3. 获取与启动

### 3.1 使用已编译版本（推荐）

1. 在仓库的 Releases 页面下载 `OpenSeat-…-win-x64.zip`（私有仓库需登录有权限的 GitHub 账号）。
2. 解压到任意可写的文件夹。
3. 双击 `OpenSeat.exe`。程序没有代码签名，Windows 可能弹出 SmartScreen 提示，选择“更多信息 → 仍要运行”。

### 3.2 从源码编译

1. 把源码解压到可写目录。
2. 双击 `start.cmd`：脚本会调用系统自带的 C# 编译器生成 `dist\OpenSeat.exe`，然后启动它。
3. 若提示找不到编译器，请安装或修复 .NET Framework 4.x 后重试。
4. 编译成功后，`dist\OpenSeat.exe` 可以单独复制到别处使用。

### 3.3 运行自检

双击 `self-test.cmd`，程序会编译并执行 20 项自检（配置校验、保存/读取、输入数据解析、按键去重、设备名称解析等），完成后弹窗显示结果。

自检**不需要**三屏硬件，但通过自检**不代表**硬件已验收。

## 4. 界面说明

主窗口从上到下分为七个区域：

1. **标题栏**：显示版本号和“完整桌面隔离尚未实现”的提醒。
2. **工具栏**：刷新设备 / 屏幕、显示屏编号、保存配置、导入配置、导出配置、虚拟机工位…，以及“屏幕监控”开关。
3. **屏幕监控栏**（0.2.2 起）：位于工位卡片上方，三格实时缩略图分别显示三个工位显示器的画面，约每秒刷新 2 次。点击任一缩略图会打开该工位的放大监控窗（见第 8.1 节）。
4. **三张工位卡片**（工位 1、2、3），每张卡片包括：
   - **名称输入框**：可以把“工位 1”改成“前台”“小王”等，最多 40 个字符。
   - **显示器下拉框**：显示屏幕名、分辨率、位置，以及是否为主屏，例如 `DISPLAY2 · 1920×1080 · 位置 (1920,0)`。
   - **绑定鼠标** / **绑定键盘** 按钮。
   - **清除此工位绑定** 按钮。
   - **绑定状态**：显示设备的 VID/PID（厂商号/产品号）和 [在线] / [离线]。
5. **测试控制**：启动（停止）三屏输入测试、停止 / 取消绑定、导出诊断报告。
6. **设备清单区**：列出所有屏幕、所有 Raw Input 鼠标和键盘，以及每个工位的绑定情况。
7. **状态栏**：显示当前操作的结果或提示，遇到问题先看这里。

## 5. 完整操作流程

### 第 1 步：准备显示器

连接三台显示器。在 Windows“设置 → 系统 → 屏幕”中选择**扩展这些显示器**。

### 第 2 步：刷新设备

点击 **刷新设备 / 屏幕**。在下方设备清单中确认能看到三块屏幕和至少三个鼠标。

### 第 3 步：确认每块屏幕的编号

点击 **显示屏编号**。每块屏幕左上角会弹出一个小窗口，显示屏幕名（如 `DISPLAY1`）以及它目前分配给哪个工位，约 2.5 秒后自动关闭。

### 第 4 步：给工位命名（可选）

在每张工位卡片的名称框中输入名字。测试窗口的标题会使用这个名字。

### 第 5 步：为每个工位选择显示器

在三个下拉框中分别选择**不同**的显示器。同一块屏幕不能分给两个工位。

### 第 6 步：绑定鼠标

1. 点击工位 1 的 **绑定鼠标：稍后移动它**。
2. **等 1 秒**，然后**只移动**工位 1 要用的那个鼠标，其他鼠标不要碰。
3. 状态栏显示“绑定完成（VID … · PID …）”即成功。20 秒内没有操作会超时，重新点按钮即可。
4. 对工位 2、工位 3 重复以上步骤。

### 第 7 步：绑定键盘（可选）

点击 **绑定键盘：稍后按一下**，等 1 秒后在对应键盘上按一个键（比如 A）。没有多套键盘可以跳过，鼠标测试照样能进行。

### 第 8 步：保存配置

点击 **保存配置**。配置只有在点击保存时才写入磁盘；如果关闭程序时有未保存的修改，程序会提醒你。

### 第 9 步：启动测试

点击 **启动三屏输入测试**。如果某个工位缺少显示器、鼠标离线或设备重复，程序会拒绝启动并说明原因。

启动后，每块屏幕会出现一个深蓝色的测试窗口，显示：

- 工位名称
- **鼠标事件**：收到的鼠标数据包数量
- **点击**：左键、右键、中键和侧键的按下次数
- **按键**：物理按键次数（长按产生的自动重复已过滤），括号中是原始按键事件数
- **蓝色圆点**：程序画的测试指针，跟随对应鼠标移动

### 第 10 步：观察结果

依次操作三套设备，看是否**只有对应工位的窗口**在变化。详见第 6 节。

### 第 11 步：结束测试

以下任一方式都会停止全部测试：

- 在任一测试窗口按 **Esc**；
- 关闭任一测试窗口；
- 在主窗口点 **停止三屏输入测试** 或 **停止 / 取消绑定**。

## 6. 如何判断测试结果

| 你看到的现象 | 说明 |
|---|---|
| 移动鼠标 A，只有工位 1 的蓝点在动 | 正常，设备区分成功 |
| 移动一个鼠标，两个工位的计数都在增加 | 不应出现；请导出诊断报告检查绑定 |
| 移动鼠标，没有任何窗口变化 | 程序可能不在前台（见第 9 节），或该鼠标未绑定 |
| 系统白色光标也跟着所有鼠标动 | 正常。系统光标是共享的，程序不阻止 Windows 原有输入 |
| 长按一个键，“按键”只加 1，原始事件不断增加 | 正常，自动重复已被过滤 |

## 7. 配置文件、导入与导出

- 默认配置文件：`%LOCALAPPDATA%\OpenSeat\three-seat.xml`（可在资源管理器地址栏粘贴这个路径打开）。
- **导出配置**：把当前配置另存为 XML，方便备份或复制到另一台电脑。
- **导入配置**：读取 XML，先校验，校验通过才替换当前配置；导入后需要再点 **保存配置** 才会写入默认位置。
- 保存使用“临时文件 + 原子替换”，即使保存失败也不会损坏原有文件。
- 设备 ID 和插口有关：把鼠标换到另一个 USB 口后，通常需要重新绑定。导入到另一台电脑后也需要重新绑定。
- 0.1 版（Python 配置器）的配置与本版不通用。

## 8. 诊断报告

点击 **导出诊断报告**，保存为 `.txt` 文件。报告包括：

- 系统版本；
- 每块屏幕的名称、分辨率和位置；
- 所有鼠标、键盘的 VID/PID 和完整设备路径；
- 每个工位的绑定以及在线状态。

报告**不包含**任何按键内容或输入的文字。但它含有设备标识，分享给他人前请留意。

### 8.1 屏幕监控

- 工位卡片上方的三格缩略图显示每个工位当前分配的显示器画面。没有分配显示器的工位会显示“未分配在线显示器”。
- **点击缩略图**会打开放大监控窗，约每秒刷新 5 次；窗口可以拖动和调整大小，按 Esc 或点关闭按钮退出。同一工位只会打开一个监控窗，再次点击会把它切到前面。
- 取消勾选工具栏的 **屏幕监控** 可以暂停缩略图刷新，节省 CPU。
- 监控是**只读**的：只截取画面，不会向工位发送鼠标或键盘输入。
- 锁屏、UAC 提示等 Windows 安全桌面无法被截取，此时会显示“暂时无法捕获画面”。
- 如果把放大监控窗放在它正在监控的那块屏幕上，会出现“画中画”的重复效果，这属于正常现象。

## 9. 常见问题

**问：点了“绑定鼠标”，移动鼠标却一直不成功，最后超时。**
答：请确认点按钮后**等满 1 秒**再移动；只移动目标鼠标；OpenSeat 主窗口要在前台（不要切换到其他程序）。

**问：提示“这个设备已绑定到某某工位”。**
答：一个设备只能属于一个工位。先在原工位点 **清除此工位绑定**，再重新绑定。

**问：两个鼠标被识别成同一个设备。**
答：一些“二合一”无线接收器（如一个接收器同时连鼠标和键盘，或多个设备共用一个接收器）会把多个设备合并成一个。程序无法拆分这种设备，请换用独立接收器或有线鼠标。

**问：测试时计数突然不动了。**
答：程序只统计**自己在前台时**的输入。如果点到了其他程序的窗口，请点回任一测试窗口。

**问：状态栏显示“已绑定的输入设备被拔出，测试已停止”。**
答：重新插好设备，点 **刷新设备 / 屏幕**，确认卡片上显示 [在线]，必要时重新绑定。接入**新的**设备不会中断测试，只会在状态栏提示。

**问：状态栏显示“显示拓扑发生变化，测试已停止”。**
答：屏幕被插拔或分辨率改变了。刷新后核对每个工位的显示器选择。

**问：启动时提示“某工位未分配在线显示器”。**
答：该工位的下拉框为空，或保存的屏幕当前未连接（会显示“未连接”）。重新选择一块在线屏幕。

**问：Windows 提示“已保护你的电脑”。**
答：这是因为程序没有代码签名。确认文件来自你自己的仓库后，选择“更多信息 → 仍要运行”。

## 10. 已知限制

- 不是独立桌面：系统光标、桌面、音频和其他应用仍然共享。
- 只路由到本程序的测试窗口，不向其他软件发送输入。
- 只统计本程序处于前台时的输入。
- 触摸屏、数位板等绝对坐标设备只映射到测试画布，不代表真实桌面位置。
- 复合无线接收器可能无法区分。
- 三套真实硬件尚未完成验收；RTX 3050 及以上显卡的兼容性未经验证。
- 未提供安装程序、驱动或代码签名。

## 11. 隐私与安全

- 不联网，不需要账号、激活码或授权。
- 不需要管理员权限，不修改系统安全策略，不安装驱动。
- 不记录按键字符、输入文本或密码。

## 12. 0.2.1 版本改进

- **修复：绑定和测试被误停止。** 程序注册设备通知时，Windows 会对已连接的设备发送“到达”通知，旧版会把它当作设备变化而立刻停止。新版忽略已知设备，只有**已绑定的设备被拔出**时才停止。
- **按键计数更准确**：过滤长按自动重复，区分左右 Ctrl/Alt 等按键。
- **点击计数**包括右键、中键和侧键。
- **工位卡片**显示设备 VID/PID 和在线状态；显示器下拉框显示分辨率、位置和主屏标记；“显示屏编号”弹窗显示这块屏幕属于哪个工位。
- **工位可以改名**（最多 40 个字符）。
- 错误提示更清楚（名称无效、XML 损坏等）；停止、导入、导出、清除时状态栏都会给出反馈。
- 自检由 14 项增加到 20 项，并新增 GitHub Actions 自动编译和自检。

## 14. 虚拟机工位：三人各用独立的 Windows（0.3.0）

### 14.1 原理

- **工位 1（主机工位）**：直接使用这台电脑本身的 Windows。
- **工位 2、工位 3（虚拟机工位）**：各运行一台 VMware Workstation 虚拟机，每台都是完整的 Windows，可以安装和运行任意软件。
- OpenSeat 把每个虚拟机工位绑定的鼠标和键盘写成 **USB 直通**。虚拟机开机后，这套键鼠从主机上“拔走”，只属于这台虚拟机，所以三个人同时操作也互不干扰。
- 每台虚拟机的窗口会被移到该工位的显示器上并最大化。

### 14.2 硬件和授权要求

| 项目 | 要求 |
|---|---|
| CPU | 在 BIOS/UEFI 中开启虚拟化（Intel VT-x 或 AMD-V），建议 8 核及以上 |
| 内存 | 建议 32 GB 及以上（主机约 8 GB + 每台虚拟机约 8 GB） |
| 硬盘 | 每台虚拟机至少 64 GB，建议放在 SSD 上 |
| 鼠标/键盘 | 三套必须是**不同型号**（VID/PID 不同），并且是 USB 有线或 USB 接收器，**不能用蓝牙** |
| Windows 授权 | 每台虚拟机里的 Windows 都需要自己的授权 |

> 为什么要不同型号？VMware 是按“型号”（VID/PID）把设备接到虚拟机的。如果两个鼠标型号相同，VMware 分不清是哪一个。遇到这种情况，OpenSeat 会拒绝写入配置并提示你。

### 14.3 安装 VMware Workstation Pro

1. 登录 Broadcom 支持门户，下载 VMware Workstation Pro（目前个人和商业用途都免费）。
2. 按默认选项安装，安装完成后重启电脑。
3. OpenSeat 会自动在注册表和默认安装目录中查找 `vmware.exe`；如果找不到，可以在虚拟机工位窗口里点 **手动指定…**。

### 14.4 创建两台 Windows 虚拟机

对工位 2 和工位 3 各做一次：

1. 打开 VMware Workstation，选择 **文件 → 新建虚拟机**，用“典型”向导。
2. 选择 Windows 安装 ISO 文件。
3. 虚拟机名称建议写成 **工位2**、**工位3**。OpenSeat 会用这个名称找到虚拟机窗口，所以两台的名称不要相同。
4. 处理器 2～4 核，内存 8 GB，硬盘 64 GB 以上。
5. 安装 Windows，然后在 VMware 菜单中选择 **虚拟机 → 安装 VMware Tools**，并按提示完成安装。
6. 在虚拟机里装好要用的软件。
7. **关机**（在虚拟机里点“开始 → 关机”）。写入直通配置时，虚拟机必须处于关机状态。

### 14.5 在 OpenSeat 中设置

1. 确认三套键鼠都插在主机上，并且两台虚拟机都已关机。
2. 在主窗口按第 5 节的方法，为三个工位**选择显示器、绑定鼠标和键盘**，然后点 **保存配置**。
3. 点工具栏的 **虚拟机工位…**，打开设置窗口。
4. 工位 1 保持“主机工位”；工位 2、工位 3 分别点 **选择…**，选中对应虚拟机的 `.vmx` 文件（在虚拟机所在文件夹里）。
5. 看窗口底部的“方案检查”。如果有问题（比如型号相同、用了蓝牙设备、少绑了鼠标），按提示处理。
6. 点 **① 写入 USB 直通配置**。OpenSeat 会先把原文件备份为 `.vmx.openseat-backup`，然后写入直通设置。
7. 回到主窗口点 **保存配置**，记住虚拟机的选择。

### 14.6 每天的启动顺序

1. 打开 OpenSeat，点 **虚拟机工位…**。
2. 点 **② 启动虚拟机工位**。两台虚拟机会开机，窗口会被自动移到工位 2、工位 3 的屏幕上并最大化。
3. 虚拟机开机后，工位 2、工位 3 的键鼠会自动接入各自的虚拟机，这两位同事就可以开始使用了。
4. （可选）需要全屏时：用**主机工位**的鼠标点虚拟机窗口菜单 **查看 → 全屏**。虚拟机工位的键鼠已经直通给虚拟机，VMware 收不到它们的快捷键，所以这一步要用主机的键鼠完成。
5. 勾选 **把主机鼠标锁定在主机工位屏幕**。这样主机用户的鼠标不会移到其他两块屏幕上，也就不会误点虚拟机窗口。按 **Ctrl+Alt+F12** 可以随时解锁或重新锁定。

> 注意：鼠标锁定只在“虚拟机工位”窗口打开期间有效。这个窗口可以最小化，但不要关闭。

### 14.7 关机与还原

- 下班时，在每台虚拟机里正常关机。关机后，直通的键鼠会自动回到主机。
- 如果想撤销 OpenSeat 对 `.vmx` 的修改，先关机，再点 **还原 .vmx 备份**。
- 如果虚拟机异常退出，导致键鼠没有回到主机，把它拔下来重新插上即可。

### 14.8 虚拟机工位的限制

- **显卡**：虚拟机使用 VMware 的虚拟显卡，用不上主机的 RTX 显卡，大型 3D 游戏和专业 3D 软件在虚拟机里会很慢或无法运行。需要高性能 3D 的人应该坐在主机工位。
- **声音**：三个工位默认共用主机的扬声器。建议每个工位用一个 USB 耳机，然后在每台虚拟机的 **设置 → 声卡** 中选择对应的耳机设备。
- **同型号设备**：无法区分，必须使用不同型号的键鼠。
- **一体接收器**：如果键盘和鼠标共用一个 USB 接收器，它们会作为一个整体直通，只能用于同一个工位。
- **主机工位的保护**：OpenSeat 不会启用 `allowLastHID`，所以 VMware 不会抢走主机工位的最后一套键鼠。
- 屏幕监控（第 8.1 节）同样能看到虚拟机工位的画面。
